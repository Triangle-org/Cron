# Triangle Cron

Triangle Cron подключает планировщик Localzet Cron к приложению на Triangle Engine как отдельный процесс с одним worker. Компонент читает задания из `config('cron')` и регистрирует их при запуске этого процесса.

## Требования

- PHP `^8.1`
- Triangle Engine `^9.0`
- Localzet Server `^7.1` (устанавливается вместе с Engine 9)
- Localzet Cron `^2.0`

Версия 2.x предназначена для Engine 9 и Server 7. Приложения на Engine 8 и Server 4 должны оставаться на Triangle Cron 1.x.

## Установка

```sh
composer require triangle/cron:^2.0
```

Добавьте задания в `config/cron.php`:

```php
<?php

return [
    [
        'name' => 'cleanup-expired-records',
        'rule' => '*/5 * * * *',
        'callback' => static function (): void {
            // Run a short, non-blocking task here.
        },
    ],
];
```

Правила из пяти полей задают расписание с точностью до минуты. В правилах из шести полей можно указать секунды. Callback выполняется в event loop Localzet Server: он должен быть коротким и неблокирующим. Длительную работу передавайте в очередь или отдельный процесс.

## Работа во время запуска

При подготовке Engine к запуску сервера (`start` или `restart`) компонент регистрирует отдельный сервер `Cron` с одним worker. В обработчике `onServerStart` этого worker он читает `config('cron', [])` и регистрирует задания, в которых заданы непустые `rule` и `callback`.

Это планировщик в памяти процесса, а не надёжная очередь заданий. Расписание не сохраняется между перезапусками; компонент не согласует задания между отдельными установками приложения. Оставляйте один worker планировщика, если приложение специально не должно выполнять каждое задание на каждом worker.

## Проверки

```sh
composer install
composer run check
```

Проверка совместимости подтверждает контракт автозагрузки Engine 9, создание процесса планировщика через механизм запуска Server 7 и загрузку только полных описаний заданий. CI запускает проверки на PHP 8.1–8.5.
